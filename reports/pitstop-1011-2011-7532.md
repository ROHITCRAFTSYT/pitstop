### Fix lookup_customer parameter name (customer_email->email), fix tag list matching in search_kb, and embed priority policy in SYSTEM prompt
Round 1 · commit `970d9270fc` · 2 more check(s) pass

**Root cause.** The TOOL_SPECS definition declares the parameter as 'email', so the LLM calls lookup_customer({"email": "..."}) — but the actual Python function signature is `def lookup_customer(customer_email: str)`. ### Fix search_kb to match any query token against article title/tags instead of full-string substring match
Round 3 · commit `cda5454297` · 5 more task(s) pass

**Root cause.** The search_kb function checks if the entire lowercased query string (e.g. 'webhook delivery failure') is a substring of the article title or tags. KB article titles and tags likely contain individual words like 'webhook' but not the full phrase, so every search returns []. Fix: split the query into tokens and match if ANY token appears in the title or any tag. Also fix the system prompt priority policy to match policy.py (add past_due P2 rule and clarify enterprise non-outage is P2).
